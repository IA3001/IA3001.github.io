1002 数字王国的警报密码

Problem Description

给定 n,kn,kn,k，构造出长度为 nnn 的且任意子区间的和不等于 kkk 的严格单增的字典序最小的序列，不存在输出 −1-1−1。

数据范围：∑k≤2×106\sum k \le 2 \times 10^6∑k≤2×106

Solution

暴力构造、全局懒标记 Trick

  • 根据鸽巢原理和一些推导，可以知道最多只能有 k−1k-1k−1 长度的解
  • 于是就模拟向右扩展新的数字 ppp，扩展步骤如下：
    • 扩展数字时，新的区间为所有以新数字为结尾的区间，需要查询是否存在一个之前序列的后缀和（可以是 0）与新的数字相加恰好模 kkk 等于 000
    • 也就是说，是否存在 k−pk-pk−p 同余的后缀和，即 pre[((k-p)%k+k)%k]==true；如果存在，不断的 ++p 直到不存在对应的"敌人"即可
    • 一旦确定该数字，就需要更新新序列的各种后缀和，显然为 {之前的所有后缀和+p}∪{0}\{\text{之前的所有后缀和}+p\} \cup \{0\}{之前的所有后缀和+p}∪{0}，关键的来了！
      • 我们想要求解新的 pre[] 结构，绝对不能暴力
      • 通过全局懒标记，即使用一个 d 表示全局加，想要让所有元素 +=v 直接令 d+=v 即可
      • 查询 v 是否存在时，由于所要查询的 v 其实是在 pre[] 中 +=d 得到的，所以为了找到它的真实状态需要相应的 -=d，即查询 v−dv-dv−d

踩坑

  • UNK：由于我不熟练 全局懒标记，导致花了太长时间推导调试！
    • （赛时被卡的地方）关于新元素 000 加入我认为是相反的，就搞反了。**事实上，读/写一个元素，所需要的下标是相同的！**如果想全体加 ppp 然后新增一个 000，很简单，先 d=(d+p)%kd=(d+p)\%kd=(d+p)%k（一定要取模啊！），然后 pre[((0-d)%k+k)%k]=true
    • 全体加 vvv 只需要 tag+=v！
    • 读/写 vvv 只需要 arr[v-tag]！
  • WA：平移参数这种变量，不断的加数字，必然可能会爆 int，但是我没有注意

Code

pre[0]=true;
int d=0,p=1;
while(ans.size()<n){
    if(!pre[((k-p-d)%k+k)%k]){
        ans.push_back(p);
        d=(d+p)%k;// 一定要注意啊 如果不取模 或者开 LL 容易爆 int 啊
        pre[((0-d)%k+k)%k]=true;
    }
    p++;
}

1003 回文串

Problem Description

在 S,TS,TS,T 中分别选取非空子串 S′,T′S',T'S′,T′，顺次拼接为 S′+T′S'+T'S′+T′ 恰好为回文串，求方案数。

数据范围：n≤2000n \le 2000n≤2000，T≤10T \le 10T≤10

Solution

Manacher + DP，O(n2)O(n^2)O(n2)

想象一下最终回文串的组成方式（前提：S′=Tr′S' = T'_rS′=Tr′​）：

  • 要么 S′+T′S'+T'S′+T′
  • 要么 (S′+S’后附加回文)+T′(S' + \text{S'后附加回文}) + T'(S′+S’后附加回文)+T′
  • 要么 S′+(T’前附加回文+T′)S' + (\text{T'前附加回文} + T')S′+(T’前附加回文+T′)

所以翻转一下 TTT 即可，变为计算所有 [S′=Tr′]×计数权重[S' = T'_r] \times \text{计数权重}[S′=Tr′​]×计数权重。

设：

  • dp[i][j]\text{dp}[i][j]dp[i][j] 表示从 S[i],Tr[j]S[i], T_r[j]S[i],Tr​[j] 开始，合法匹配的方案数，答案即为 ∑1≤i≤n,1≤j≤mdp[i][j]\sum_{1 \le i \le n, 1 \le j \le m} \text{dp}[i][j]∑1≤i≤n,1≤j≤m​dp[i][j]
  • f[i]f[i]f[i] 表示 S[i]S[i]S[i] 开头作为回文串的方案数
  • g[i]g[i]g[i] 表示 Tr[i]T_r[i]Tr​[i] 开头作为回文串的方案数

dp[i][j]={0S[i]≠Tr[j](1+f[i+1]+g[j+1])+dp[i+1][j+1]S[i]=Tr[j]\text{dp}[i][j] = \begin{cases} 0 & S[i] \ne T_r[j] \\ (1 + f[i+1] + g[j+1]) + \text{dp}[i+1][j+1] & S[i] = T_r[j] \end{cases} dp[i][j]={0(1+f[i+1]+g[j+1])+dp[i+1][j+1]​S[i]=Tr​[j]S[i]=Tr​[j]​

使用 Manacher 计算回文半径，离线区间 +1 即可算出 f[i],g[i]f[i], g[i]f[i],g[i]。

踩坑

    • 设 s 是文本串（n 长度），p 是模式串（m 长度）

    • lcp 数组是 s 计算出的 n 长度的，表示 s 的各个位置开始的后缀与 p 的 lcp

1004 炼金术士的配方

Problem Description

给出一个长度为 nnn 数组 aaa，求满足"区间乘积后仅保留奇数次幂的质数的去重集合与 xxx 的集合相等"的子区间 [l,r][l,r][l,r] 数量。

（另一种阐述）bitset<1e6> A[5e5] 区间异或和等于给定 bitset<1e6> X 的方法数。

数据范围：2≤n≤5×1052 \le n \le 5 \times 10^52≤n≤5×105，1≤a[i]≤1061 \le a[i] \le 10^61≤a[i]≤106，1≤x≤1061 \le x \le 10^61≤x≤106

Solution

计数、随机化映射、01集合压缩映射

  • 首先，传统的维护前缀异或和的方式复杂度太大，其瓶颈在于：
    • 虽然初始每个 A[i]A[i]A[i] 中 1 的数量是 log 级别的，但是合并会导致 1 状态达到 nnn 级别
  • 我们尝试化简，压缩集合使其变得精简，这需要随机化映射的辅助，保证低出错概率
    • 即传统的集合存储方式，我们使用了信息保留量 100% 的方式
    • 现在将一个大的 O(n)O(n)O(n) 级别的集合映射为一个 O(1)O(1)O(1) 级别的哈希值，同时要满足易于维护任意质数的插入与删除
    • 显然，集合全体值的异或是一个不错的方式：当插入/删除一个质数时，只需要异或上它的基础映射值即可
  • 但是现在我不会证明它的准确性 QAQ

1009 力的平衡

Problem Description

给定 k≤500k \le 500k≤500 个规模 ≤100\le 100≤100 二维的力 FFF，可以重复使用，求最小的合力为 000 所需的使用量。

数据范围：∑k≤1000\sum k \le 1000∑k≤1000，T≤10T \le 10T≤10

Solution

合理地缩小判定范围、BFS

  • 由于向量的合成，力自然可以围成一个凸包环，但是合成过程中，可能会达到距离原点很远的地方。
  • 注意到不需要严格规定使用次序，且单个向量的移动能力有限，完全可以划定一个足够小的有限的定义域范围，使得所有力的合成都在定义域范围内进行（类比挪车的辅助空间）
  • 故以单个力的规模 100100100 为块单位，两个维度范围均设置为 444 个单位块长度左右即可

1010 MEX

Problem Description

给出 mmm 个关于值域为 [0,n−1][0,n-1][0,n−1] 排列数组 a[1…n]a[1 \dots n]a[1…n] 的信息 xi,yix_i,y_ixi​,yi​，表示 mex a[x…n]=y\text{mex } a[x \dots n] = ymex a[x…n]=y，求数组 aaa 的可能方案数。

Solution

计数、排列组合

不想不知道，一想就知道。当你手玩，尝试从 p=n+1p=n+1p=n+1（表示已经填过数字的边界）开始填数字的时候，cur=0\text{cur}=0cur=0（已经填过的数字的 mex 值），你就会发现：

  • 可选数字会被 y[1…p]y[1 \dots p]y[1…p] ban 掉，否则不符合 mex 定义
  • 并且在处理 xi,yix_i,y_ixi​,yi​ 时，必须保证在 a[xi…p−1]a[x_i \dots p-1]a[xi​…p−1] 区间内所有的值域在 [cur,y−1][\text{cur}, y-1][cur,y−1] 的数字都必须已经被使用，有一个非常细节的地方：
    • 注意到区间 [cur,y−1][\text{cur}, y-1][cur,y−1] 中，只有 cur\text{cur}cur 是之前一直被 ban 掉的
    • （cur<y−1\text{cur} < y-1cur<y−1 的情况）cur\text{cur}cur 必须在这一段区间内被选择（被"安排"了），而 [cur+1,y−1][\text{cur}+1, y-1][cur+1,y−1] 的数字，则必然不是被 ban 掉的，所以可以在之前的任意未被"安排"操作的位置填充，然后那些未被"安排"的位置也被设置为"安排"
    • 所以需要维护一个被"安排"的余量 rrr

Code

int r=n;
int cur=0,p=n+1;
LL ans=1;
for(int i=m;i>=1;i--){
    auto [x,y]=xy[i];
    int l = p-x;
    int h = y-cur;
    if(h>0)r--;
    LL tk=C(l,h>0)*A(r-x+1,h-(h>0))%mod;
    r-=(h-(h>0));// 要减掉 已经使用过的 x 位置 
    ans=ans*tk%mod;
    p=x;
    cur=y;
}
