## 随机化 Tricks（竞赛实战完全手册）

> **心法**：随机化不是赌博，而是利用概率制造“以极高概率正确的多项式算法”。赛场上如果正解极其复杂或对时限压力大，这就是救命稻草。

### 1. Color Coding（颜色编码）
- **核心思想**：给图的节点随机染成 $k$ 种颜色，强制目标路径/子图必须是“彩虹色”（每种颜色恰好出现一次），然后在这个强化条件下进行状压 DP。跑多次随机染色，只要有一次成功找到即为正确。
- **实现细节**：
  - 状态设计：`dp[mask][v]` 表示当前走过颜色集合为 `mask` 且终点为 `v` 的路径是否存在（或最小费用）。
  - 转移方程：`dp[mask | (1<<color[u])][u] = max(dp[mask | (1<<color[u])][u], dp[mask][v] + 1)`（前提是 v 和 u 有边，且 u 的颜色不在 mask 中）。
- **概率分析**：目标路径长度为 $k$，单次随机染色其恰好为彩虹色的概率为 $\frac{k!}{k^k} \approx \sqrt{2\pi k} e^{-k}$。尝试 $T$ 次后失败的概率为 $(1 - \frac{k!}{k^k})^T$。当 $k=5$ 时，概率约 $0.04$，跑 100 次成功率近乎 100%。**建议尝试次数设为 2000~5000 次**（看时限）。
- **经典应用**：CF 1648D / CF 1616H / 求图中的长度为 $k$ 的简单路径或环。

### 2. 随机黑白染色 / 二分图强制
- **核心思想**：很多图论难题在二分图上有极漂亮的性质（如无奇环）。我们可以把原图随机分为两个点集（黑和白），强制只允许从黑走到白（或白走到黑），从而把原图变成二分图。如果原图的目标结构恰好是偶环/偶路径，多试几次总能被我们随机到。
- **实现细节**：
  - 给每个点随机赋 $0/1$ 颜色。强制修改原图边权：若 $color[u] == color[v]$，则该边不可走（设为INF）；否则可走。
  - 在每次染色形成的二分图上跑 DP（如 Floyd 或最短路）。
- **概率分析**：如果目标回路或路径长度为 $L$（边数），每条边两端颜色不同的概率是 $\frac{1}{2}$，所以整体被保留下来的概率是 $2^{-L}$。因此**只适用于 $L$ 较小（$\le 15$）的情况**。
- **经典应用**：CF 1310D - Tourism。求从 $1$ 出发回到 $1$ 经过 $k$ 条边的最短路，且不能有奇环。由于 $k \le 10$，随机黑白染色后跑 $k$ 次矩阵乘法即可。

### 3. XOR Hashing（异或哈希）
- **核心思想**：为每个元素分配一个随机大整数，通过集合的异或和来判断两个集合是否相等。这比直接存集合或排序快了 $O(N \log N)$。
- **实现细节**：
  - 使用 `std::mt19937_64 rng(chrono::steady_clock::now().time_since_epoch().count());` 初始化。
  - 分配权值：`val[i] = rng();`。
  - 集合 $S$ 的哈希值：$H(S) = \bigoplus_{x \in S} val[x]$。
  - 若 $H(A) == H(B)$，则 $A$ 与 $B$ 大概率相等（错误率 $2^{-64}$）。
- **高阶技巧**：在树结构中，用异或哈希判断两个子树是否完全对称、判断路径上的字符集合是否相等。
- **经典应用**：CF 1746F - Kazaee（区间出现次数为 k 的倍数）、CF 1830C - Hyperregular Bracket Strings（判断括号序列的合法集合交并）。

### 4. 随机化贪心（Randomized Greedy）
- **核心思想**：在贪心决策时随机打乱输入顺序，或者以一定概率接受次优解。单次贪心可能陷入局部最优，但跑 $T$ 次取最优，就能以极高的概率逼近全局最优。
- **实现细节**：
  - 跑 $T$ 次循环（通常 $T = 100 \sim 1000$，看时限）。
  - 每次循环内，`std::shuffle(a.begin(), a.end(), rng);`
  - 对打乱后的数组跑常规贪心逻辑，更新答案。
- **注意事项**：如果题的答案要求极其精确，随机化贪心可能会 WA。但在许多工程题或启发式搜索题中，这能骗到极高的分数。
- **经典应用**：最大独立集、最小顶点覆盖的近似解、CF 上的许多构造题（随机乱搞可过）。

### 5. 模拟退火（SA） / 爬山法
- **核心思想**：在解空间中随机游走。爬山法只接受更优解，极易陷入局部最优；模拟退火引入了“温度” $T$，允许以 $P = e^{-\frac{\Delta E}{T}}$ 的概率接受劣解，从而跳出局部最优。
- **实现细节**：
  - 设初始温度 $T_0 = 2000$，终止温度 $T_k = 10^{-15}$，降温系数 $\Delta T = 0.999$。
  - 循环条件：`T > T_k && clock() < 0.9 * CLOCKS_PER_SEC`。
  - 每次在当前解附近随机扰动产生新解，计算能量差 $\Delta E$。
  - 若 $\Delta E < 0$，接受；否则以概率 $e^{-\Delta E / T}$ 接受。
  - 降温：`T *= 0.999;`
- **调参技巧**：几何问题、数值优化中，退火参数直接决定成败。可以多跑几次 SA，每次的随机种子不同。
- **经典应用**：CF 2C（Commentator problem，最小圆覆盖/几何退火）、求多峰函数最值。

### 6. 随机增量法（Randomized Incremental Algorithm）
- **核心思想**：对于某些线性空间或计算几何问题，按顺序加入元素，如果加进来的元素破坏了当前最优解，就强制以该元素为基础重建最优解。为了打破输入顺序的“最坏情况”，**先随机打乱输入数组**。
- **概率/复杂度分析**：以最小圆覆盖为例，假设前 $i$ 个点已经在最小圆内，加入第 $i$ 个点，它作为“边界点”的概率是 $O(1/i)$。经过严谨的期望分析，总复杂度从 $O(n^3)$ 降为 $O(n)$。
- **经典应用**：最小圆覆盖（Minimum Enclosing Circle）、最小包围球、线性规划（半平面交的随机增量求解）。
- **最小圆覆盖核心代码逻辑**：
  ```cpp
  shuffle(p, p+n);
  Circle c = {p[0], 0};
  for (int i = 1; i < n; i++) {
      if (!c.contains(p[i])) {
          c = {p[i], 0};
          for (int j = 0; j < i; j++) {
              if (!c.contains(p[j])) {
                  c = { (p[i]+p[j])/2, dist(p[i],p[j])/2 };
                  for (int k = 0; k < j; k++) {
                      if (!c.contains(p[k])) {
                          c = circumcircle(p[i], p[j], p[k]);
                      }
                  }
              }
          }
      }
  }
  ```

### 💡 给你的实战建议：

赛场上遇到随机化题，**第一件事是写一个 `mt19937` 的种子**（`chrono` 防 Hack）。然后观察时限：
*   时限 1s，通常能跑 $10^7$ 次基本操作，如果单次操作是 $O(N)$，那只能跑 100 次；如果单次是 $O(1)$，那可以跑几千次。
*   CF 的题如果是随机化正解，出题人通常会把时限放宽到 2s 或 3s，这就意味着你可以暴力多跑 2000 次以上。
